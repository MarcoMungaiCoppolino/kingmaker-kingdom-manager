# Kingmaker Kingdom Manager — the code manual

This manual explains **how the app is built today** and **where every feature lives in the
code**. It is written for two readers: whoever programs (and wants to know where to put their
hands) and an assistant picking the work up in a new session (who must know how everything is
connected without re-reading twenty-five thousand lines).

It is not a version history: that is [`../devlog.md`](../devlog.md). Where a choice comes from
a defect seen while playing it is said in one line — «before X happened, now Y» — and no more.
The whole water model — network, routes, the ruler on the water — is [chapter 9](09-water-travel.md). The user's view of the same features is the
[user guide](../user-guide.md).

## How to read it

The chapters are in dependency order: each uses only things explained before it. Whoever is in a
hurry reads the **Overview** and then jumps to the chapter they need. Every concept appears with
**the name it has in the code**, in `monospace`, so a search takes you from the text to the source.

## The three rules that hold everywhere

1. **The game data comes from the rules, never invented.** Mechanics live in
   `kingmaker/rules/data/*.json`; the texts in `rules/data/lang/<language>/`, transcribed from Archives of
   Nethys (English) and pf2.altervista.org (Italian), each file with its `_source`. What the rules
   do not say is marked `"source": "table"` and explained in the in-app Manual.
2. **Effects are proposed and confirmed, never applied in silence.** An activity, a structure, a
   journey: the program computes, shows, and waits for a click. It is the same rule for the
   water read from the image and for imported charts.
3. **A player never receives what they do not know.** The filter is in the server (`access/view.py`),
   not in the CSS: what is not theirs enters neither the SVG nor the ruler payload.

## The figures

The figures of this manual in `img/` are generated by `manual_figures.py` with the real drawing
functions of the app (`hexmap._svg_grid`, `hexmap.waters_network`) on a copy of the test scene.
The diagrams are Mermaid, which GitHub renders by itself. The screenshots in `img/screenshots/`
were taken from the app on a copy of a real table, with the English interface; the same pictures
with the Italian interface are in `img/screenshots/it/`, for the Italian README and guide. Chapter 11 says how to retake
them. The geometric figures of the water (chapter 9) are made by `water_figures.py`, in `img/` too.
The drawings of the architecture (chapter 14, `img/architecture-*.svg`) are plain SVG drawn by
hand, with their own stylesheet and a ground, so GitHub shows them in either theme.

## Where things are

```
launch.py                start (local, --lan, --online with NiceGUI On Air; --launcher)
launch_test.py           a copy of the app on port 8081, on separate data
kingmaker/               the package, one folder per layer of the graph in chapter 1
  main.py                the pages, the header, the in-app Manual
  cli.py                 the command line shared by launch.py and the installed app
  config.py              paths and network from the environment
  launcher/              the window that starts and stops the server (core.py, window.py),
                         the cloud (dropbox.py, sync.py, wizard.py, guide/), the windows
                         kept inside small screens (screen.py)
  state.py               STATE: the kingdom in memory and the derived statistics
  rules/                 the rules: __init__.py (loader, indexes, dice), almanac.py
                         (calendar), data/ (mechanics) and data/lang/<code>/ (texts)
  locale/                i18n.py (t(), one catalog per language in lang/), units.py
  geometry/              hexgrid.py, sections.py (faces), atoms.py (the 24 pieces),
                         waterways.py (the boats' network)
  water/                 reading.py (the image reading), chart.py (the water charts)
  travel/                __init__.py (costs, paths, plan, rendezvous, routes), daily.py
  storage/               archive.py (schema, migrations, queries), migrations.py,
                         legacy_names.py (the Italian → English maps of schema 27)
  access/                auth.py, permissions.py, view.py: identity, roles, who sees what
  media/                 images.py, imgsize.py: uploads and thumbnails
  ui/                    theme.py (shell, refresh bus), login.py, badges.py, icons.py;
                         tabs/ (sheet, turn, city, creation, party, transport, clock,
                         gm_screen); hexmap/ (the map: nine modules and the facade in
                         __init__.py); static/ (travel_drag, water_eraser, water_current,
                         map_scroll .js)
packaging/               the frozen app: PyInstaller spec, Inno Setup script, build.py, the icon
tests/                   the suite: run_all.py, the scene built from scratch, the benches
tools/                   the four checkers and the 1.0.0 release tools
docs/                    this manual, the user guide, the devlog
saves/                   the live database (NOT versioned, NEVER touched by the tests)
assets/                  the map image and the tokens (not versioned)
```
